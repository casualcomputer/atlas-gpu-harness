# Real Strata policy experiments

The demo uses the actual **Strata v0.1.43 engine** (source commit `7695859aa13afb248bdb4d36f9b2e95707db079d`) on native Windows, an RTX 5070 Ti, Intel i7-14700F, and 64 GB RAM. Its supported model is **Qwen3.8-Flash-Next IQ2_XS**, downloaded by Strata's pinned installer (68.03 GB across two GGUF shards). The experiment inputs are generated repository-review documents; all inference and runtime counters come from the real engine.

Open [the policy lab](demo-ui/strata.html). It reads [the Atlas export](evidence/strata/latest.json), refreshed after each committed experiment. An absent result stays pending. The browser has no MongoDB credentials.

## Protocol fixed before the experiment

- **32,768 actual input tokens in every trial**, for both tuning and confirmation. The owner limited the demo to this window before inference began. Token IDs are constructed using the model's tokenizer and saved with an SHA-256 checksum. The engine must report the same input count and zero reused prompt tokens. The allocated context includes an additional 1,024 tokens for output.
- Three tuning seeds and three different confirmation seeds. Each document contains eight distributed deployment settings, two subsequent amendments, and unrelated generated code. The answer must retrieve the final values and their sum. Reasoning is disabled for this demo. An explanation is requested to exercise a longer decode, capped at 768 tokens. Only the exact values and sum are graded; this is not a general reasoning or prose-quality benchmark.
- Five real Strata policies: shipped defaults, four CPU expert workers, seven CPU expert workers, aggressive expert-cache adaptation (160 swaps every window, decay 0.97), and PCIe expert offload disabled. These are documented Strata controls derived from its [calibration implementation](https://github.com/Niko1221/Strata/blob/v0.1.43/tools/calibrate.py). No policy here was generated by an LLM.
- Each trial starts a fresh engine and uses the same separate warmup. Tuning order rotates across blocks; confirmation alternates default/candidate order. Quantization, speculative decoding, KV streaming, and model files stay fixed across policy comparisons. The GPU expert cache is sized by Strata for the allocated context.
- A tuning candidate must pass all three quality/execution checks and exceed the default's median decode throughput by 3%. The choice is committed **before** reading any confirmation result. It is retained only if all three matched pairs on **fresh 32K prompts** pass, each with a decode improvement greater than 3%. If tuning selects the default, only its fresh-prompt coverage is measured; no policy gain is claimed.
- Report every repeat, median and observed range, plus prefill speed, first-token latency, expert hits/lookups, offloaded experts, draft acceptance, and engine file counters. One-second resource samples record GPU usage and process RSS/I/O. GPU samples include other processes; process read bytes are not a physical SSD measurement. Three repeats give descriptive variability, not a significance claim.

This section describes the earlier **Strata-versus-Strata policy experiment**. A later [single-pair engine comparison](INFERENCE_RESULTS.md#new-32k-engine-comparison--october-11-2026) used identical Qwen weights and 32K input IDs: llama.cpp **18.22 tok/s**, Strata **107.77 tok/s** (**5.92× observed**). It compares different runtime optimization bundles, including Strata MTP4 and reported expert skipping; it is not an isolated policy improvement. Both engines retrieved 8/8 document values and both had the same arithmetic mismatch. The earlier Kimi results cannot supply the Qwen comparison denominator.

## Persistence and recovery

The runner uses the existing `runs`, `experiments`, and `decisions` collections in MongoDB Atlas. Each trial has a deterministic identity, an owner-token completion, an attempt count, raw model output, command, prompt artifact, quality result, engine counters and resource samples. Decisions reference earlier experiment IDs. The exported evidence is read back from Atlas after every completion, with a dangling-reference check.

`--stop-after 1` exits after a durable commit. `--resume RUN_ID` retrieves it and continues without re-running completed or failed trials. Engine, source, model metadata and protocol changes invalidate resume. A local file lock prevents duplicate controllers in the same OS; this is not a distributed scheduler.

## Reproduce on this native Windows installation

From the repository directory in PowerShell:

```powershell
artifacts\Strata\.venv\Scripts\python.exe -m pip install -e ".[harness]"

artifacts\Strata\.venv\Scripts\python.exe -m atlas_gpu_harness.strata_experiment `
  --strata-root artifacts\Strata `
  --config artifacts\Strata\strata-iq2_xs.json `
  --stop-after 1

# Use the ATLAS_RUN_ID printed by the first command.
artifacts\Strata\.venv\Scripts\python.exe -m atlas_gpu_harness.strata_experiment `
  --strata-root artifacts\Strata `
  --config artifacts\Strata\strata-iq2_xs.json `
  --resume RUN_ID
```

The environment needs `pymongo`, `python-dotenv`, `filelock`, and `psutil` in addition to Strata's own dependencies. The repository `.env` supplies `MONGODB_URI`; credentials are never exported. Strata was installed with `--family qwen --model IQ2_XS --context 131072 --vision no --low-ram off --no-start`, with all model files under `artifacts/Strata-data`. Weights and the third-party runtime are ignored by Git.

The project-downloaded Kimi and Qwen GGUF files and selected unused Windows Ollama models were removed with the owner's authorization to free storage. Their earlier benchmark evidence is retained.

## Results

Run `e5359ac4eb6d42358187f0530d66b1d9`, October 11, 2026. The five-policy tuning grid is complete: three different 32K prompts per policy, 15 actual engine requests. Reasoning stayed disabled throughout.

| Policy | Decode median (tokens/s) | Observed range | Prefill median (tokens/s) | Full correctness |
| --- | ---: | ---: | ---: | ---: |
| Strata default (13 workers) | 108.00 | 76.49–114.43 | 2,875 | 0/3 |
| 4 CPU workers | 98.59 | 75.41–107.34 | 2,819 | 0/3 |
| 7 CPU workers | 105.10 | 103.50–110.60 | 2,839 | 0/3 |
| Adaptive cache, 160 swaps | 114.73 | 103.58–115.86 | 2,867 | 0/3 |
| PCIe offload disabled | 101.71 | 93.43–102.03 | 2,864 | 0/3 |

Adaptive cache changes produced an **observed +6.2% median decode difference** versus Strata default. This is not a validated optimization: all 15 tuning requests retrieved the eight final settings correctly, including both amendments, but failed the arithmetic total. The strict gate rejected every arm. Default throughput ranged from 76.49 to 114.43 tokens/s, illustrating why the first request alone is an unreliable comparison. The generated answers and speculative-decoding acceptance also vary, so these rates are workload-specific.

This policy sweep therefore does not promote a faster candidate or establish a comparison to llama.cpp. Its useful output is a measured policy distribution, an explicit quality failure, and a reproducible experiment record. The three fresh-prompt default checks also failed the total while retrieving all eight settings. **All 18 requests completed real inference and processed exactly 32,768 uncached input tokens; 18/18 passed the setting lookup, 0/18 passed the full check.** The final run has no validated recommendation. No reasoning-enabled or additional-context trial was run.

The [independent Atlas read-back audit](evidence/strata/audit.json) verified 18 experiment records, 18 decisions, 153 resolved evidence links, zero dangling references, and attempt 1 for every experiment. One deliberately interrupted controller recovered its already committed first trial without repeating it. Source and tokenized-prompt checksums match. The [complete export](evidence/strata/latest.json) and per-trial engine logs preserve the failures and raw telemetry.
